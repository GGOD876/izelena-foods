01Outcome and decision

Make the approved 5173 React/Vite prototype the visual and interaction source of truth, then reimplement it as a WordPress classic theme with WordPress-native content, a WooCommerce integration boundary, and Docker-first local development.

Visual target1:1same hierarchy, spacing, palette, imagery, responsive states, and interaction intent
Editorial controlWP-nativepages, menus, logo, hero copy, products, images, and contact details editable by admins
PortabilityDocker → managedlocal Compose maps cleanly to managed WordPress hosting and WooCommerce
Approved boundaryThe prototype remains preserved as a visual regression oracle. WordPress owns production content and commerce. No new visual direction is introduced during parity work unless required for an accessibility or platform fix.

03Parity definition

Visual parity
  • Same announcement strip, logo treatment, navigation order, headline hierarchy, CTA prominence, and section rhythm.
  • Same brand colors: Island Ink, Sorrel Red, Scotch Yellow, Mango Leaf, Mango Gold, Pantry Cream, and white.
  • Same supplied asset usage and equivalent fallbacks when WordPress content is absent.
  • Same responsive breakpoints and no horizontal overflow on mobile.
Behavior parity
  • Navigation reaches the same destinations from header, footer, hero, product cards, Scotchimeter, and wholesale CTA.
  • Filters, heat links, product details, cart/add-to-cart, menu toggle, and contact affordances have clear states.
  • Loading, empty, unavailable, and WooCommerce-not-installed states remain intentional.
  • Keyboard users can reach and operate critical controls.
Parity rule: prototype state → WordPress state → expected result → evidence URL or screenshot → owner sign-off Example: Shop / Hot → /shop/?heat=hot → only hot products or approved empty state → desktop + mobile evidence → QA accepted

07WooCommerce boundary

Theme owns
  • Card composition, visual styling, heat badge, CTA labels, archive layout, detail wrapper, related-product presentation, empty states.
  • Design tokens, responsive CSS, accessibility, and no-plugin fallback.
WooCommerce owns
  • Products, variations, prices, stock, cart, checkout, orders, emails, coupons, shipping, tax, and gateways.
  • Powertranz/PayPal only after merchant and legal confirmation.
Commercial guardrailCatalogue prices, retail/wholesale basis, MOQs, shipping, returns, tax, payment terms, and food-service pricing require confirmation before checkout is enabled.

12Accessibility

  • One meaningful H1 per route with readable heading order.
  • Visible keyboard focus for navigation, buttons, filters, product actions, and form fields.
  • Mobile menu exposes button semantics and aria-expanded.
  • Images have meaningful alt text; pattern backgrounds stay decorative.
  • Yellow/green surfaces use dark text; red/black surfaces use white text.
  • Product states include unavailable, coming soon, empty, out-of-stock, and error messaging.
  • Contact form has labels, privacy consent, spam protection, validation, and success/error response.

14Delivery phases

Phase 0 — Freeze the reference

Confirm the 5173 build, capture route/viewport evidence, and lock copy, assets, palette, and expected states.

Phase 1 — Shell parity

Match announcement, header, menu, footer, tokens, buttons, assets, containers, and focus states.

Phase 2 — Homepage parity

Match hero, featured products, Scotchimeter, story preview, wholesale CTA, spacing, art crop, responsive stack, and empty states.

Phase 3 — Page/routing parity

Match Shop, Our Story, Contact, Wholesale, route helpers, Docker rewrites, and managed-host permalinks.

Phase 4 — WooCommerce parity

Install WooCommerce in staging; map products, images, heat, variants, stock, cart, checkout, order, and payment boundary.

Phase 5 — Diff, harden, migrate

Run visual/accessibility/interaction QA, rehearse DB/uploads migration, and obtain managed-host approval.

15Acceptance gates

Parity
  • Approved routes match prototype structure and responsive behavior.
  • No P0/P1 visual, routing, accessibility, or interaction defects.
  • Design tokens and supplied assets are respected.
WordPress
  • Theme activates on a fresh install.
  • Admin can edit logo, menus, hero, contact data, pages, products, images, and heat.
  • Theme works without WooCommerce for design review.
Migration
  • Managed staging runs without local rewrite mount.
  • DB/uploads/theme migration is rehearsed.
  • HTTPS, backups, permalinks, and rollback are confirmed.
Business
  • Price basis, MOQs, variants, content, policies, and recipients are approved.
  • Client signs off 5173 vs 8080 evidence.
